# ADR-002: Separate Staging and Production Instances

## Status
Accepted

## Date
2026-11-12

## Context
The Aviation DMS requires two environments: a staging environment for testing and validation, and a production environment for operational use. Initially, production containers were deployed on the bastion host and the staging instance, which was incorrect. The production environment must be on a dedicated instance with strict security controls.

## Decision
- **Staging**: Cloud instance `10.20.4.234`, dev mode (`DEV_MODE=true`), 1 GB storage quota, ports 8001/8081.
- **Production**: Dedicated OCI instance `10.20.1.69` (Ubuntu 26.04 aarch64), strict security (`DEV_MODE=false`), 30 GB storage quota, ports 8000/8080, HTTPS via bastion Caddy reverse proxy.
- Independent `dms_data` volumes for each environment; volumes are never shared.
- Bastion `145.241.152.126` runs Caddy as TLS termination for `roc.kfl.ke` → production proxy.

## Rationale
- **Security isolation**: Production handles operational records, KCAA evidence, and personnel credentials; staging uses test data. Separate instances prevent accidental cross-environment data exposure.
- **Quota differentiation**: Staging limited to 1 GB to prevent unbounded test data growth; production approved for 30 GB by the Records Custodian.
- **Configuration separation**: Production uses `DMS_TRUSTED_FRONTEND_IP=145.241.152.126/32` (bastion IP), HTTPS-only cookies, CSRF, and origin allow-listing; staging uses dev-mode identity headers.
- **Fail-closed deployment**: Production promotion requires manual approval gate; staging deploys automatically on push to `main`.

## Consequences
- **Positive**: Clear environment boundaries, production security controls, no test data in production, independent backup/restore per environment.
- **Negative**: Two instances to maintain, bastion dependency for production HTTPS, port conflict resolution on staging (8000→8001, 8080→8081).
- **Mitigation**: Deployment scripts (`deploy-staging.sh`, `deploy-prod.sh`, `promote-to-production.sh`) automate environment-specific deployment; Caddy on bastion handles TLS termination.

## Alternatives Considered
- **Single instance with namespaces**: Rejected due to insufficient security isolation for aviation compliance records.
- **Terraform-provisioned OCI instance**: Terraform files removed; production instance created manually and managed directly via bastion.

## Review
Review if additional environments (e.g., UAT, disaster recovery) are required.
